# 控制卡到位后联调清单

> 前提：EZCAD 控制卡 + 激光设备已连接。
> 每一步写明了预期现象和失败时优先排查顺序。

---

## 1. 环境检查

| 检查项 | 命令/方法 | 预期 | 失败时排查 |
|--------|-----------|------|-----------|
| 32位 Python 存在 | `tools\py32\python.exe -c "import struct; print(struct.calcsize('P')*8)"` | 输出 `32` | 重新解压 `python-3.12.8-embed-win32.zip` 到 `tools/py32/` |
| Lmc1.dll 存在 | `dir "D:\...\Ezcad2.14.11(20220909)\Lmc1.dll"` | 文件存在，约 640KB | 确认 EZCAD 安装路径 |
| 配套 DLL | 同目录下 `LMCMIO.dll`, `DataMgr.dll` 存在 | 两个文件均存在 | 重新安装 EZCAD |
| 端口 9701 未被占用 | `netstat -ano | findstr 9701` | 无输出（端口空闲） | 换端口: `--port 9702` |

---

## 2. 启动 bridge

```cmd
cd "Y:\仪达\009 激光打码同步标签打印\三码合一程序"
tools\py32\python.exe bridge\bridge_stub.py --port 9701
```

预期输出：
```
[Lmc1Bridge Stub] 启动在 http://127.0.0.1:9701/api
[Lmc1Bridge Stub] DLL 路径: D:\...\Lmc1.dll
```

失败排查：
1. 检查 32位 Python 路径是否正确
2. 检查 bridge_stub.py 是否存在
3. 检查 DLL 路径中是否含中文/空格导致 ctypes 加载失败（当前已知可加载）

---

## 3. 验证 bridge 在线

```js
// F12 Console 或独立 HTTP 工具
fetch('http://127.0.0.1:9701/api', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({id:'1',cmd:'Ping'})}).then(r=>r.json())
```

预期：`{ok:true, data:{pong:true}}`

失败排查：
1. bridge 进程是否仍在运行
2. 防火墙是否拦截本地 9701 端口
3. 如有代理，需对 127.0.0.1 关闭代理

---

## 4. Init — DLL 加载探测

```js
fetch('http://127.0.0.1:9701/api', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({id:'2',cmd:'Init'})}).then(r=>r.json())
```

预期：`{ok:true, data:{exportsFound:17, exportsTotal:17, exportsMissing:[]}}`

失败排查：
1. `LMC1_0001` → DLL 文件不存在，检查路径
2. `LMC1_0002` → Python 位数与 DLL 不匹配（需 32位 Python）
3. `exportsMissing` 非空 → 导出名可能有版本差异，记录缺失列表

---

## 5. OpenDriver — 打开激光驱动 ⭐

```js
fetch('http://127.0.0.1:9701/api', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({id:'3',cmd:'OpenDriver',params:{driverIndex:0}})}).then(r=>r.json())
```

预期（有控制卡）：`{ok:true, data:{returnValue:0}}`

已知：无控制卡时也返回 0。返回值语义待控制卡到位后进一步确认。

失败排查：
1. `LMC1_9999` 异常 → 检查 DLL 是否被其他进程占用
2. 返回非 0 → 记录具体值，可能为驱动错误码

---

## 6. GetLmcDev — 获取设备对象 ⭐⭐ (关键验证点)

```js
fetch('http://127.0.0.1:9701/api', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({id:'4',cmd:'GetLmcDev'})}).then(r=>r.json())
```

**有控制卡预期**：`{ok:true, data:{returnValue:"0x...", isNull:false}}` — 非空指针。

**无控制卡当前**：`{ok:true, data:{returnValue:"NULL", isNull:true}}`。

> 这一步是通过/不通过的**分水岭**。如果 `isNull:true`，则无法继续后续所有步骤。

失败排查：
1. `isNull:true` → 检查控制卡是否安装、驱动是否正常
2. 确认 EZCAD 软件本身能否正常打开和控制激光
3. 如果 EZCAD 软件正常但 bridge 返回 NULL → DLL 可能依赖 EZCAD 主进程的初始化

---

## 7. InitLmc — 初始化设备对象 ⭐⭐

> 前提：第 6 步 `isNull:false`

```js
fetch('http://127.0.0.1:9701/api', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({id:'5',cmd:'InitLmc',params:{param1:0,param2:0}})}).then(r=>r.json())
```

预期：`{ok:true, data:{returnValue: ...}}`

注意：
- `param1`, `param2` 语义未确认。先用 (0, 0)。
- `__thiscall` 调用方式为假设（将 this 指针作为第一参数）。如果返回异常，可能需要调整调用方式。

失败排查：
1. `LMC1_0003` → GetLmcDev 返回了 NULL（回到第 6 步）
2. `LMC1_9999` 异常 → 可能是 thiscall 调用方式不兼容。记录异常信息。
3. 返回非 0 → 可能是初始化错误码，记录具体值

---

## 快速验证脚本（控制卡到位后一次性执行）

```js
(async () => {
  const api = (cmd, params={}) => fetch('http://127.0.0.1:9701/api', {
    method:'POST', headers:{'Content-Type':'application/json'},
    body: JSON.stringify({id:'x', cmd, params})
  }).then(r=>r.json());

  console.log('1. Ping:', (await api('Ping')).ok);
  console.log('2. Init:', (await api('Init')).data?.exportsFound + '/17 exports');
  console.log('3. OpenDriver:', (await api('OpenDriver',{driverIndex:0})).data?.returnValue);
  console.log('4. GetLmcDev:', (await api('GetLmcDev')).data?.isNull ? 'NULL ⛔' : 'NON-NULL ✅');
  console.log('5. InitLmc:', (await api('InitLmc',{param1:0,param2:0})).ok ? 'OK' : 'FAIL');
})();
```

预期输出（有控制卡）：
```
1. Ping: true
2. Init: 17/17 exports
3. OpenDriver: 0
4. GetLmcDev: NON-NULL ✅
5. InitLmc: OK
```

## 失败时优先排查顺序

1. bridge 进程是否在运行 → Ping
2. DLL 是否能加载 → Init
3. 控制卡驱动是否正常 → EZCAD 软件本身能否工作
4. 端口/防火墙 → 9701 是否可访问
5. Python 位数 → 必须是 32位
6. DLL 版本 → Ezcad2.14.11
