## 三、核心数据流

```
用户选型号
  │
  ▼
modelConfigBlock.getCurrentModel()
  │
  ▼
BusinessData.fromModel(model)          ← 创建统一数据对象
  │
  ▼
serialCodeBlock.generateCode(model)    ← 生成 22位码
  │
  ▼
BusinessData.attachCode(codeResult)    ← 绑定码数据
  │
  ├─→ BusinessData.getTemplateVars()  ← 模板变量 map
  │       │
  │       ├─→ laserEzcadAdapter.setVariables() → startMark()
  │       │       └─→ lmc1Bridge.send('StartMark', {variables})
  │       │               └─→ fetch('http://127.0.0.1:9701/api', POST)
  │       │
  │       └─→ printerAdapter.sendZpl(zpl)
  │
  ├─→ BusinessData.toRecord(status)    ← 写入 traceLogBlock 内存存储
  │
  └─→ uiMapper.refreshAll()            ← 页面刷新
```

## 四、关键文件职责一句话

| 文件 | 一句话 |
|------|--------|
| `businessData.js` | 各模块间唯一数据载体，消除散落字符串拼接 |
| `deviceResult.js` | 统一设备返回结构，mock/real/real_error 区分 |
| `laserEzcadAdapter.js` | 激光适配器：init/reset/dispose/redLight/startMark，桥接集成 |
| `lmc1Bridge.js` | HTTP 通信骨架：真实 fetch→失败→回退 mock |
| `bridge-protocol.json` | 桥接协议正式定义：10条命令(Init/LoadTemplate/SetVariables/RedLight/StartMark/GetStatus/GetLastResult/Reset/Shutdown/Ping)、14个错误码 |
| `station1PrintBlock.js` | 工位一状态机：调试→自动→3业务执行→自动循环 |
| `station2MarkBlock.js` | 工位二状态机：调试→自动→扫码识别→扫码打码→自动循环 |
| `traceLogBlock.js` | 四级分类日志：生产/扫码/设备/报警 |
| `ui-text.json` | 所有按钮/标题/提示文案 |
| `variable-mapping.json` | 三类模板的字段分配表 |
| `lmc1-known-unknown.md` | DLL 探测结论：已确认/推断/未确认 |

## 五、Lmc1.dll 探测结论摘要

| 项目 | 结论 |
|------|------|
| DLL 类型 | MFC C++ DLL, 32-bit x86 |
| 导出符号 | **232 个 C++ 函数** (非 COM)；已通过32位 ctypes 验证 **17/17** 关键导出可访问 |
| 核心类 | `CLmcDev` |
| 初始化 | `lmc_OpenDriver` → `gf_GetLmcDev` → `InitLmc` |
| 打码链 | `ReadyMark` → `MarkEnt` → `Run` → `WaitForMarkFinish` |
| MFC 依赖 | MFC42u.DLL, `SetOwen(CWnd*)` |
| COM 注册 | **无** |
| SDK 文件 | 未发现可直接用于 Lmc1 二次开发的头文件/官方 SDK 文档。仅发现 `PARAM/MarkParam.lib`（898字节），用途待确认 |
| Bridge 首选候选 | C++ MFC 32位进程 + LoadLibrary（待 CEntity/变量写入 API 确认后定型） |
